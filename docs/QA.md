# 検証記録

## 検証スクリプトの動かし方

`scripts/` の2本は配布物には含めない。走らせるときだけ `public/` に置く。

```bash
mkdir -p public && cp scripts/*.js public/
```

開発サーバのコンソールで：

```js
const s = document.createElement('script'); s.src = '/playthrough.js';
document.head.appendChild(s); s.onload = async () => console.log(await window.__playthrough('hidden'));
```

検証が終わったら `public/` を削除して元に戻す。

## 自動プレイ検証（`scripts/playthrough.js`）

ブラウザに読み込ませ、実際のホットスポット処理を意図した順で叩き、
世界が正しい状態に達したかを検査する。フラグを直接立てる箇所は無く、
「非表示のホットスポットを叩こうとしたら失敗」「カメラ移動中は待つ」など、
実際のクリックと同じ制約を課している。

対象：全9謎、アイテム合成2件、写真4枚の復元、蓄光の三字、三つの結末。
検査項目 **54件**。

主な検査内容（抜粋）：

| 項目 | 期待 |
|---|---|
| 通電にはヒューズが要る | レバー単独では上がらない |
| 生きている受け金には差せない | 真ん中の空きにだけ入る |
| クランクを持たずには差せない | 六角の穴の説明だけが出る |
| 鍵なしでは暗室は開かない | 錠が落ちたままだと言われる |
| 違うバットには注げない | ラベルの合ったバットにだけ移せる |
| ネガなしでは像が出ない | 白い光が壁に落ちるだけ |
| 番号が違えば金庫は開かない | 環が回りきらない |
| 現像には液と赤い明かりが同時に要る | どちらか欠けると断られる |
| 四工程の出典を見ずに環を揃える | 閂は落ちない |
| 錠が外れることと館を出ることは別 | 二段階の行為 |

結果：**54/54 通過**。三つの結末すべてに到達。

## 到達性の走査（`scripts/reachability.js`）

各視点で全周（48方位 × 11仰角 × 7×7 のレイ格子）を掃き、
登録されたホットスポットのうち実際にクリックで到達できるものを数える。
これで「登録されているが、どこからも指せない」＝実質のソフトロックを検出する。

結果：**70件中65件が到達可能**。到達しなかった5件はいずれも正しく条件付き：

| 未到達 | 理由 |
|---|---|
| hall / studio / office / dark:phosphor | 安全灯（赤）の下でのみ出現。走査は夜明けの状態で実施 |
| studio:backdrop | 幕を巻き上げたあとは幕そのものが存在しない（差分は巻き上げ時に自動記録済み） |

安全灯の状態で同じ走査を行った場合は **70件中67件**（残る3件は未解決の謎に紐づく正当な条件付き）。

### この走査で見つかった実際の不具合

1. **近接視のホットスポットが親のクリックを奪っていた** ― 同じ形状に複数の
   ホットスポットが紐づくと、後から登録したものが上書きしていた。受付の抽斗、
   額、椅子、軸、年代記、バット、薬品棚、乾燥ロープ、鍵板が
   **すべてクリック不能**だった。形状に id の配列を持たせ、いま有効なものを
   選ぶ方式に変更して解消。
2. **撮影灯の台座に形状が無かった** ― 位置マーカー用の空グループに近接視を
   紐づけていたため、暗室の鍵が永久に入手不能だった。実体のある撮影灯へ変更。
3. **入口で振り返れなかった** ― 視点の水平可動域が狭く、ホールへ戻る床の印が
   背後に隠れていた。当時は全視点を全周（±π）可動に変更して解消。
   （固定構図への作り替えにあわせて、この問題は「四つの画面が輪になって
   一周する」設計そのものに置き換わっている。下の「固定構図への作り替え」を参照）
4. **事務室の予約控が机に埋まっていた** ― 高さを上げ、専用の当たりを持たせた。

## 独立レビュー

作者以外の視点で三本の査読を実施し、指摘を反映した。

### 日本語（41件の指摘）
主な修正：
- 解錠の場面で「錠が落ちる」（＝施錠側の語）を使っていた → 「錠が外れる」
- ピントグラスで**鏡文字**は読めない（大判カメラは像を180度回す）
  → 壁の書き込みを天地逆に変更し、関連する全文を修正
- 現像液はこぼれても燃えない → 石油ストーブを火元に接続
- 今夜焼いた印画紙の裏に四十年前の鉛筆書きがあった → ネガの袋へ移動
- 「一歳の誕生日」と四歳・七歳の日付が一か月ずれていた → 撮影日を七月に統一
- 暗室のバットに「撮影」があった（撮影は暗室の外の仕事） → 「水洗」に変更
- 表記ゆれ（抽斗／引き出し、暗室時計／タイマー、玄関ホール／ホール）の統一
- 金庫の数字だけ半角数字だった → 漢数字に統一
- カタカナ・敬体・「〜する必要がある」構文の除去

### 謎の公平性（重大5件・高4件・中7件）
- **背景幕を巻き上げると観察の謎が永久に解けなくなる** → 巻き上げ直前に、
  その時点で正当に観察可能な差分を自動記録
- **椅子の裂け目・額の台紙がクリックできない** → 優先度で解決
- **玄関の錠が開始1分で解けて、そのままゲームが終わる** → 工程の出典を
  一つも見ていない場合は閂が落ちない。加えて退出を別の行為に分離
- **一度結末に到達するとセーブが死ぬ** → 結末到達後は退出フラグを解除
- 手がかりの穴（「灯の下」と「赤の下の三字」に手がかりが無かった）→ 2件追加
- ヒントの段階が強すぎたもの2件を降格

### 実装（重大2件・高6件・中多数）
- **トーンマッピングとsRGB出力が一度も適用されていなかった** ―
  EffectComposer は HDR ターゲットに描くため、three は画面に描く最後のパスに
  しか適用しない。`OutputPass` を挿入し、パス順を
  `Render → Bloom → Output → Grade → SMAA` に修正。
  これに合わせて照明の強度を全面的に再調整した。
- **退出フラグがセーブに残り、ロードすると結末に到達できなくなる** → 解除
- 引き伸ばし機の投影・現像済みの一枚・三脚の抽斗・持ち去った物の
  再出現など、ロード時に復元されていなかった世界の状態を追加
- 合成後に材料がもう一度拾えた → ガードを追加
- 文書パネルがスクロールできなかった（`pointer-events`）
- 毎フレームの走査・確保（時計の針の探索、Vector3 の生成）を除去
- 影マップの大きさを画質設定が一律に潰していた → 各光源の設定を基準に

## 固定構図への作り替え（第二版）

自由に見回せるカメラをやめ、部屋ごとに四つの固定画面を置く方式に変えた。
これは見た目の変更ではなく**仕様の変更**である。見回せた頃は「その物が
画面に入っているか」は演出の問題だったが、固定構図では**入っていない物は
永久にクリックできない**。したがって構図は目視ではなく実測で担保する。

### 到達性の実測

`scripts/reachability.js` は、16画面それぞれに **121×121本の光線**を
画面いっぱいに飛ばし、実際に当たったホットスポットを記録する。
走査は **4:3**（縦画角から作れる最も狭い横画角）で行う。ワイド画面でしか
入らない構図を「入っている」と数えないためである。

| 状態 | 到達 | 内訳 |
|---|---|---|
| 開始直後 | 39 / 48 | 未到達9件のうち7件は条件付きで正当（安全灯下でのみ出る蓄光の三字、幕を上げるまで存在しない年代記の壁、現像するまで存在しない一枚、点灯するまで存在しない投影）、2件は扉のホットスポットに隠れている出口（下記） |
| すべて解錠した状態 | 45 / 48 | 残る3件は上記の出口2件と、巻き上げ後は存在しない背景幕 |

### この走査で見つかった実際の不具合（いずれも人間には詰み）

1. **配電盤が受付の画面に紐づいていた** ― 実際には西の壁にあり、受付の視線から
   68度ずれている。最初の謎が始められなかった。西の画面へ。
   （ヒントの一段目は最初から「西の壁に鉄の箱が掛かっている」と書いてあった。
   文章のほうが正しく、実装が追いついていなかった）
2. **階段がどの画面にも入っていなかった** ― 結果として玄関ホールの東の画面は
   何も無い壁だけになっていた。東の画面へ。
3. **大判カメラと撮影灯の台座が画面の外にあった** ― ピントグラスの謎と
   暗室の鍵が両方とも入手不能。東・南の画面へ組み替え。
4. **物干し線に吊るしたネガが薬品棚の画面から一メートル外れていた** ―
   引き伸ばし機の画面へ。
5. **受付の抽斗・傘立て・鍵板は、ワイド画面でだけ入っていた** ― 4:3 では外れる。
   立ち位置と画角を組み直した。

### 扉の不具合

扉の板には「錠を開ける」ホットスポットと「通り抜ける」出口の両方が
紐づいており、前者が当たり判定を取る。そのため**解錠したあとに扉を押しても
「もう開いている」と言うだけで、暗室にも事務室にも入れなかった**。
解錠済みの扉を押したら通り抜けるように変更し、三つの戸口すべての往復を
自動テストの項目に加えた。

### 幾何の不具合

- **階段**：手すりが段板と逆向き（35度）に傾いていた。手すり子はすべて高さが
  二倍で、手すりを一メートル突き抜けていた。踏面と蹴上げから手すりの高さを
  計算し直し、親柱を追加。さらに**階段全体が外壁を突き抜けて建物の外に
  はみ出していた**ため、内側へ移動。
- **受付台**：箱に平らな板を一枚貼っただけだった。台輪・框・中桟・鏡板を持つ
  枠組み構造に作り直した。
- **階段上の目張り板**：中間色の木で、明るい壁の前ではほぼ同じ明度になり
  消えていた。濃い材に変え、壁から離して影が出るようにした。

### 近接視の明るさ

館の照明は雰囲気のために暗い。それは引きの絵では正しく、**近接視では
間違っている**（プレイヤーは読むために顔を寄せている）。近接視の間だけ
カメラに追従する小さな光を灯すことにした。照明状態ごとに強さを変え、
安全灯の下では暗室の前提を壊さない程度に留めている。

### 写真の露出

観察の謎に使う昭和六十年の写真が、近接視で上半分が白く飛んでいた。加えて
ガラスの鏡面反射が絵の中央に光の玉を作っていた。**差分を探させる当の一枚**で
起きていたので、印画紙を艶消しに、ガラスを拡散寄りに変更した。

### 嘘の設定を消した

- 「あそびかた」がまだ「画面をドラッグ」「床の印を押す」と説明していた。
- 設定に「視点の感度」「視点の上下」が残っていた。保存もされていたが、
  どこにも繋がっていない**回しても何も起きないつまみ**だった。削除。
- 「調べられる場所の印」は三択だったが、実際に効くのは「出さない」だけだった。
  実態に合わせて二択に。

### 試験環境そのものの不具合

これらが今まで見つからなかった理由でもある。自動プレイスルーは実時間の
タイマーで待っていたが、**待っている相手のフレームループは、タブが前面に
ないと毎秒1コマまで落ちる**。しかも `dt` は 50ms で頭打ちなので、0.6秒の
カメラ移動が実時間で10秒以上かかる。判定は世界が動く前に期限切れになり、
「進行が壊れている」ようにも「壊れていない」ようにも見えていた。

デバッグ用に `pump(秒)` を追加し、フレームレートと無関係にゲーム内時間を
直接進める方式に変えた。到達性の走査も、描画任せだった行列更新を明示的に
行うようにした（毎秒1コマの描画が残した数秒前の姿勢に対して光線を飛ばして
いた）。
